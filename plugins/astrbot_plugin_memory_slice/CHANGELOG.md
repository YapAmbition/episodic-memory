# 记忆切片 · AstrBot 插件更新记录

## v0.3.22

- 定时整理失败后保留待处理消息，下一轮按原定频率执行。模型请求超时会记录 `model_timeout`；下一次定时整理会缩小消息批次。
- 整理模型漏填标题时，已有事件沿用原标题，新事件和拆分子事件从各自正文取标题。更新事件时，漏填或置空的状态与显著程度沿用旧值。
- 普通整理收到无效 JSON 或字段校验失败时，会在调用预算内请求模型纠正一次。提交前校验事件的全部来源消息，持续失败时保留消费进度。
- README 新增私聊快速体验步骤，以及默认程序召回在固定测试集上的分组实测结果。

## v0.3.21

- 修复关注对象的证据校验反复卡住同一批消息的问题。首次失败时，普通整理会在剩余预算内请求模型纠正一次。若证据仍无效且能定位本轮来源，插件跳过该事件，记录忽略原因并推进对应消息的处理进度。同批通过校验的事件照常保存。
- 整理诊断区分缺少关注对象、消息来源有误和引文未逐字匹配等原因，方便定位失败环节。

## v0.3.20

- 整理模型把等待原因、空操作列表或可选事件资料（如检索锚点）写成 `null` 时，插件可以继续处理。来源消息、操作依据和消费进度仍须通过校验。

## v0.3.19

- 改进长事件的续篇整理。当旧事件材料无法完整放入预算时，模型可将有依据的后续进展保存为关联事件。
- 新增可轮转的插件诊断日志。在「运行监控 → 插件诊断日志」中可以查看或下载日志，通过诊断编号定位整理失败阶段和模型调用耗时。

## v0.3.18

- 召回等待向量服务返回期间，如果人物 UID、关注对象或事件关联发生变化，返回结果前会重新校验候选范围，避免带回已不符合人物筛选条件的事件。
