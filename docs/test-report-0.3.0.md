## 浏览器联调

使用独立测试空间和本机 HTTP 模型替身验证：

1. 已配置聊天模型时发送一条消息，观察到一次聊天调用，线索扩展和大模型关联调用均为零。
2. 读取历史会话和切换设置不重复执行模型召回。
3. 保存召回配置；保存并测试 embedding 后，索引仍为空，显式建立后显示 7 / 7 件就绪。
4. 本轮选择语义混合，显示语义候选、入口来源、完整事件及分阶段耗时。
5. 模拟 embedding HTTP 503，自动模式显示降级与原因；严格语义方式明确报错。
6. 显式大模型联想触发一次扩展与一次关联调用；未把替身延迟当作真实模型性能。
7. 监控可读取分路、阶段、embedding 用量与索引状态；最终设置页控制台无错误。

## 程序召回耗时

包含 10 件历史事件的隔离 SQLite 副本，5 种固定中文查询，先预热 5 次，再串行测量 50 次。使用 Linux 容器内的 ASGI TestClient，不包含公网网络或真实聊天模型；每次包含诊断记录的主体持久化。P95 采用样本的最近秩值，非监控直方图估计。

| 口径 | 平均 | P95 |
| --- | --- | --- |
| 服务报告的召回处理 | 17.03 ms | 35.51 ms |
| 测试客户端完整请求 | 25.28 ms | 47.99 ms |

外部生成式模型和 embedding 调用均为 0。该结果只验证当前小规模程序路径的耗时，不证明召回准确率，也不能推算真实 embedding 的延迟或大规模性能。
