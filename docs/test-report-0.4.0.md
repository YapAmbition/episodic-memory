原有 68 项后端测试保留，新增 29 项，主要覆盖：

- 容量未知时不依据模型名猜测，已知容量统一扣除输出与安全余量。
- 提示词、序列化、多字节字符、人物、消息和旧事件都计入估算输入预算；固定材料超限时在请求前失败。
- 仅明确上下文错误和明确输出长度终止触发缩批，普通鉴权/参数错误不触发。
- 缩批以实际材料量为依据，下一次请求真正变小；后续批次继承已缩小预算。
- 输出截断即使恰好返回可解析 JSON 也不提交；输出超限还缩小新消息量。
- 长消息按连续原文范围处理；片段成功后才推进位置，失败不跳过尾部；只在整条结束后计入完整消息数。
- 源位置可逐段还原完整原始消息（包含 emoji 与换行）。派生事件正文可能按既有 schema 修剪边界空白，原文与其位置保持不变。
- 衰减与显著度影响候选，真实重提提高鲜明度，明确细节可唤起多年旧事；程序读取不会写强化记录；遗忘权重为 0 时取消时间衰减惩罚。
- 旧事按明确范围补读，超预算或读轮次用尽时暂缓；越界/跨空间引用不写入；暂缓消息与修改来源互斥；暂缓任务可重试。
- 指标估算量与提供方用量分离，指标标签不包含原文、事件 ID、消息 ID 或密钥。

新增 4 项前端测试覆盖未知容量、已知容量预算公式、任务调用/补读/缩批展示和估算量与实际用量的区分。

## 当前边界

输入计数是保守估算，不是对应模型 tokenizer 的精确计数。未知容量无法保证首个请求成功；固定提示词、必要来源及明确指向旧事的最小材料仍放不下时，会失败或暂缓，并保留原文。候选有限、强线索识别为程序启发式，仍可能漏关联或误关联；没有用这些协议替身结果证明真实模型的事件划分质量。多批、补读和缩批可能增加调用次数，本版不承诺真实模型总耗时降低。
