# 记忆机制与整理预算

## 记忆行为

**保存**：事件正文完整保存在 SQLite，保留来源消息与历史版本，可导出为带元数据的 Markdown。每个事件有稳定 ID；正文 `[[event_id]]` 会解析为链接。模型维护以新增进展/更正追加到旧正文，保存独立片段并合并旧来源和锚点；人工编辑仍可替换当前正文，并保留旧版本。

**形成与淡忘**：发生时间与得知时间分开。当前鲜明度由初始印象、得知后的间隔、真实重提历史计算。初始幅度 `0.18 + 0.82 × salience`，保持半衰期 `half_life_days × (1 + salience_multiplier × salience²)`，随间隔指数衰减。每次有来源的强化以配置幅度贡献一条新的衰减轨迹，采用饱和叠加。所有数值都是可调工程假设，不是人类记忆概率或科学测量结果。

**唤起**：本地模式匹配时间/场景/原话/触发描述和字符二元组文本；此模式不是通用语义向量检索。全文索引覆盖正文；模型模式先提取经历结构等线索，再从全文、锚点、人物、计划日期等多路筛选候选，让模型判断有依据的入口，返回逐字依据并校验。目录使用从整篇正文寻找的相关片段，预算省略通过 retrieval 报告。候选可能漏召回，模型也可能产生牵强关联，可通过反馈和固定案例评测观察。

**传播与上下文**：沿出链及可选反链传播，乘上连接强度、传播衰减与目标记忆鲜明度。环与重复事件去重。只对激活事件读取全文；超出字符预算则省略整件事，并返回 omitted，不截断正文。`context_char_budget` 是**字符**预算，不是 tokenizer 的 token 预算。

**不会自动强化**：检索、模拟时间推进、递归读取、后台整理和配置修改都不会写入强化历史。显式强化接口和模型整理提议可以新增强化。后者需通过同一对话者、真实用户原话、已有具体细节与时间校验，可关闭 auto_reinforcement_enabled。助手复述不算强化；后台整理本身也不会强化。

**实验时间**：每次打开页面默认「实时」，聊天、召回、手动整理与事件操作自动取操作时的当前时间，无需手动刷新。切换「模拟」后固定实验时间，可指定日期或 +30 天；「恢复当前时间」直接切回实时模式。模式只在当前页面生效，不保存到服务配置，刷新页面重新默认实时。它只改变查询视角与新消息/事件的时间，不改写已有记录；早于得知时间的事件不会泄漏到过去的查询。自动整理使用服务器真实时钟，按配置时区解释每日时刻，与前端实验时钟独立。

## 整理预算与遗忘

在「模型连接」可选填写实际上下文容量和整理输出预留；留空容量也可使用。在「整理与提示词」配置输入预算、安全余量、缩批次数、补读轮次和整理遗忘权重。输入使用 UTF-8 保守估算，已知容量会扣除输出与安全预留；不会根据模型名猜测容量，未知容量不保证首次请求成功。

整理会优先考虑鲜明或线索明确的旧事。弱线索、已淡忘的事情减少进入上下文的机会；明确细节仍可唤起。读取本身不会强化或删除事件正文。候选有限，模型依然可能漏掉关联，不能把这套机制视为完美事件归属算法。

明确上下文超限或输出达到上限时有限缩批。长消息以源位置分段，成功写入后才推进；单条尾部未读不会标记整条完成。旧事可按位置补读；材料不够时任务可以暂缓，在任务详情中调整配置后重试。预算、分段范围、调用、缩批和补读次数见「整理任务」，分阶段耗时及省略原因见「运行监控」。
